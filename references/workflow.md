# FAI 气泡图制作流程 V2

## 1. 项目模式、输入与权威边界

先把 `project_mode` 记录为 `independent` 或 `revision`。默认使用 `independent`；只有用户在当前任务中明确指定基线并要求继承历史编号、坐标或版次时，才使用 `revision`。

`independent` 模式只读取用户在当前任务中明确提供或指定的输入。不得主动搜索其他项目、父级或同级目录、历史交付目录、跨会话记忆或哈希索引来寻找基线。相同 SHA-256、相似文件名或相同零件号都不能替代用户授权。

`revision` 模式建立基线输入清单，记录用户授权原文、基线路径、文件角色、SHA-256、页数、MediaBox/CropBox 和旋转。不得读取用户没有指定的其他候选基线。

- 源图纸：零件身份、材料、几何、显式公差、图面文字和技术要求的权威来源。
- 参考模板：表单结构、字段名称和视觉风格的参考来源；检具代码只有在被明确标识为受控字典时才可复用。
- 用户指定的旧台账或气泡图：可作为历史 ID 与语义映射基线；只有对应源图哈希、页面几何和旋转完全一致时，才可直接复用圆心和锚点坐标。图纸内容或页面几何变化时保留经确认的历史 ID，但必须重新定位并验证每个锚点。

模板内的示例尺寸、测量结果、批次、批准和签字不得带入新零件。

## 2. 建立特性台账

每个编号项至少记录：

- 项目模式、本次输入清单、允许读取的范围和模式依据。
- `revision` 模式下的用户授权、基线来源、历史 ID 状态和映射结果。
- 稳定 ID、页码、视图/区域和原始图纸文字。
- 规范化要求、特性类别、数值或属性模式、数量。
- 显式或默认公差依据、名义值、上下偏差、LSL、USL 和状态。
- 建议检具代码；实际设备信息必须另行填写。
- 气泡页码、中心、引线锚点、坐标系、源图哈希和适用的硬禁区版本。

另建未编号要求集合，保存原文、来源位置、检验方式、状态和冲突关联。不要把未编号要求塞进编号行。

## 3. 特性提取与去重

按主视图、侧视图、剖面/断面图、局部放大和注释逐区扫描：

- 尺寸：长度、直径、半径、角度、深度、厚度、倒角、孔距和位置。
- 形位公差：公差值、基准和被控特征一起记录。
- 属性特征：螺纹、材料/证明、外观和明确要求检验的局部特征。

同一设计要求在多个视图重复出现时，先判断是重复表达还是独立检验位置。阵列或重复特征需明确采用“一个编号 + quantity”还是逐个编号；不得同时重复计数。

## 4. 确定禁区与编号

标出技术要求区、标题栏、修订栏、签字栏、行政单元和用户指定的不编号文字区域。禁区用于圆圈、引线和箭头的几何碰撞判断。

`independent` 模式将确认后的可编号特性编号为连续 `1..N`，删除误编号文字后闭合缺口。技术要求区、标题栏、修订栏和行政单元内的可检验内容进入未编号要求集合；材料、图号、修订号等身份字段优先进入表头，不要为了延续旧数量而把它们强行变成编号特性。

`revision` 模式先对用户指定基线做合规审计：逐项核对历史 ID 的目标语义、当前存在状态和当前硬禁区。合规 ID 保留；新增项从历史最大 ID 后追加；删除项记为退役且不复用。历史 ID 落入当前硬禁区时保持 `HOLD`，不得静默继承或跳过禁区门禁。

硬禁区冲突的默认合规处置是退役历史 ID，并把仍需检验的内容移入未编号要求集合，输出旧号到新状态的映射。如果用户明确要求保留该编号，必须由用户具体重定义本项目的禁区范围并记录依据；随后用重定义后的完整禁区集合重新运行全部几何检查。不得创建只绕过单个失败气泡的隐式豁免。

## 5. 布置气泡和引线

优先把圆圈放到空白处，用短而清楚的引线指向特征。气泡白底不能盖住源图深色像素；引线走廊不能穿过尺寸文字或特征控制框，终点附近只允许很小的箭头豁免区。

自动排布后逐页检查：

- 气泡是否指向正确语义，而不只是靠近目标。
- 相邻尺寸、双向箭头、孔阵列和断面图是否发生误指。
- 当前项目硬禁区是否完全没有气泡圆、引线走廊或箭头。

## 6. 生成与反馈修订

气泡 PDF、FAI 行和检具映射必须从同一台账生成。收到反馈时先修改台账/规则，再重建全部受影响输出；不得只在 PDF 或 Excel 中单独修补，留下编号漂移。

默认最终输出只有气泡 PDF 和两表 XLSX。内部坐标台账、模式/基线授权、渲染图、检查报告和调试文件留在工作区。`independent` 模式首次交付从 `V1` 开始；`revision` 模式只依据用户指定基线的交付序列递增版次。
