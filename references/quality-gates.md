# 发布质量门禁 V2

## 项目模式与基线

- 台账明确记录 `project_mode=independent|revision`、模式依据和本次允许读取的输入清单。
- `independent` 模式不存在从其他项目、历史交付目录、跨会话记忆或自动哈希搜索得到的基线引用；首次编号为连续 `1..N`，首次对外交付版次为 `V1`。
- `revision` 模式包含用户在当前任务中明确指定的基线路径、授权内容和文件哈希；历史 ID、坐标或版次的每一种继承都在授权范围内。
- 相同源图哈希不单独构成基线授权。用户没有明确指定基线时，即使发现相同文件也按 `independent` 处理。
- 所有继承 ID 已按当前范围和禁区规则重新审计。存在冲突时保持 `HOLD`，在用户决定前不得声称质量门禁全部通过。
- 每个被声明为 `PASS` 的门禁都有本次实际运行产生的内部结果记录；不得用文字碰撞、像素检查或人工观感替代未执行的独立门禁。

## 输入与台账

- 源图和模板的哈希、页数、页面几何、旋转均已记录。
- 旧坐标只在 `revision` 模式、用户明确指定基线且对应源图哈希、页面几何和旋转完全匹配时复用；否则重新定位并验证锚点。
- ID 唯一并满足选定的连续/稳定策略；气泡、引线、台账和检验行数量一致。
- 未编号要求的 NO. 为空；不存在误编号文字、孤立气泡或孤立检验行。
- 显式公差优先；默认项包含标准、等级、单位、表/区间、限值和批准状态。
- 冲突双方及冲突键齐全，OPEN/HOLD 状态没有被普通结果覆盖。

## PDF

- 输出与源图页数、MediaBox/CropBox 和旋转一致。
- 标签集合与台账 ID 完全一致，没有缺号、重号或多余尾号。
- `PDF-G1 页面与引线`：逐个检查完整圆圈、整条引线走廊和箭头均在页面内；每个气泡有非零长度的可见引线。内部记录总数、最短引线长度和失败 ID。
- `PDF-G2 硬禁区`：逐个检查完整圆圈、整条引线走廊和箭头不进入当前项目的技术要求区、标题栏、修订栏等硬禁区。内部记录所用禁区集合、检查总数和失败 ID。
- 用户明确重定义项目禁区时，台账保存具体区域和批准依据，`PDF-G2` 使用重定义后的完整禁区集合。不得通过单个气泡的未登记豁免或跳过 `PDF-G2` 获得通过结果。
- 相邻圆心距至少为两倍气泡半径；白色气泡底覆盖源图深色像素为零。像素法默认以 300 DPI 渲染并把任一 RGB 通道低于 180/255 视为深色候选，项目可按扫描质量收紧并记录阈值。
- 引线走廊默认按线中心两侧各 1.5 pt 检查文字/矢量包围框碰撞；仅在锚点周围 3 pt 内允许箭头终点豁免。按页面比例调整时必须记录实际参数。
- 以至少 300 DPI 渲染整页和密集区域，人工确认锚点语义正确、尺寸清晰。

## XLSX

- 工作表名称、顺序和数量严格等于 `FAI检验记录`、`检具代码`。
- 编号行与气泡 ID 一一对应；未编号要求行的 NO. 为空。
- 检具型号、可测量范围和检具有效日期等必需字段存在且模板值为空。
- 所有公式引用的工作表都存在，不含 `#REF!` 或已删除页名。
- 公式错误扫描为零；使用首行、中间行、末行及边界值测试复制逻辑。
- 至少测试：显式公差 OK/NG、默认公差暂定 OK/NG、属性 OK/NG、OPEN 待确认、HOLD 优先、样本不足和非法输入。
- 在目标 Excel/LibreOffice 中强制全量重算并复核结果，不能只依赖缓存值。
- 两张表均设置打印区域；逐表渲染检查裁切、乱码、重叠、`####`、低对比和不必要的额外内容。

## 输出与放行

- 最终目录只含用户要求的 PDF 和 XLSX；无修改日志或调试文件。
- 文件名符合用户约定并使用经核实的实际运行模型名称。`independent` 模式首次交付为 `V1`；`revision` 模式只依据用户指定基线的 `V1`、`V2`、`V3` 序列递增。对外交付版次与文件内部交付元数据一致，项目语义版本和图纸修订号分别记录。
- 重新打开文件并校验容器完整性和 SHA-256。
- 交付说明写明项目模式；`revision` 模式还写明用户指定的基线和已批准偏离。不得把内部 QA 报告加入交付包，但可在交付说明中简要汇总门禁结果。
- 缺少实测值、批次/抽样信息、实际检具、校准证据、默认公差批准、OPEN/HOLD 关闭或授权签署中的任一项时，发布状态保持 `FOR REVIEW`。
